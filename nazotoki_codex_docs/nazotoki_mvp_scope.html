1. 目的

本資料は、謎解き企画用アプリを最初に動作する形まで実装するためのMVP範囲を定義する。MVPでは、演出や高度な分析よりも、イベント本番で破綻しにくい基本機能を優先する。

MVPの基本方針: 「参加者がルームに入り、問題画像を見て、解答し、正解時に得点が入る」ことを最短で成立させる。

2. MVP範囲

3. MVP対象外

以下は有用だが、MVPでは実装しない。初回リリース後に追加検討する。

  • リアルタイムランキングの常時表示
  • 複数ヒント機能
  • QRコード自動生成
  • 音声・動画問題
  • 高度な表記ゆれ判定
  • 複数出題者の権限管理
  • 詳細な解答分析ダッシュボード
  • イベント演出アニメーション
  • 複数企画テンプレート管理
MVP対象外の機能を途中で入れ始めると、完成時期が読みにくくなる。まずは「正しく得点できる」ことを完成させる。

4. 優先順位

  1. セキュリティ: 正答を参加者側に漏らさない。
  2. 得点整合性: 二重加算や不正加算を防ぐ。
  3. イベント進行: 出題者が問題開始・締切を操作できる。
  4. 操作性: 参加者が迷わず解答できる。
  5. 視認性: スマホでも画像と入力欄が見やすい。
  6. 演出性: 余力があれば見た目やランキングを改善する。

6. 完成条件

MVP完成とは、1つのルームに複数参加者が入り、出題者が問題を開始し、参加者が解答し、正解者にのみ得点が入り、出題者が得点一覧を確認できる状態を指す。
  • 参加者側レスポンスに正答が含まれていない。
  • 同じ問題に複数回正解しても得点が1回しか加算されない。
  • 出題者以外が問題作成・問題開始・締切操作をできない。
  • スマートフォン幅でも主要操作ができる。
  • 本番用URLで参加者側・出題者側の両方が動作する。
