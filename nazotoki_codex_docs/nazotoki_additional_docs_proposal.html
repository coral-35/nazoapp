2. 追加で作るとよい資料案

2.1 運用マニュアル

出題者が本番当日に使うための操作手順書。技術者ではない人が読んでも使えるように、画面ごとの操作とトラブル対応をまとめる。

  • ログイン方法
  • ルーム作成方法
  • 問題登録方法
  • 問題開始・締切方法
  • 得点確認方法
  • 本番中のトラブル対応

2.2 本番リハーサルチェックリスト

イベント前日に確認する項目をまとめる資料。本番事故を減らすうえで重要度が高い。

  • 問題画像がすべて登録されているか
  • 正答と配点が正しいか
  • 出題者アカウントでログインできるか
  • スマホから参加できるか
  • 複数人同時参加で問題ないか
  • Wi-Fi・通信環境が安定しているか

2.3 障害対応手順書

通信障害、画像表示失敗、得点不整合などが起きた場合の対応方針をまとめる。本番イベントでは「何か起きたときに誰が何をするか」が重要。

2.4 リリースノート

実装・修正ごとに変更点を記録する資料。どのバージョンで何が変わったかを追跡できる。

2.5 データ作成テンプレート

問題タイトル、正答、別解、配点、画像ファイル名などを事前に整理するためのテンプレート。問題数が増えるほど効果が大きい。

3. 優先順位

優先度資料理由
高運用マニュアル本番当日の操作ミスを減らす。
高本番リハーサルチェックリスト本番前に問題を発見できる。
中障害対応手順書通信や得点トラブル時の判断を早くする。
中データ作成テンプレート問題作成と登録作業を安定させる。
低リリースノート開発が継続する場合に有効。

4. 資料の使い方

  1. 要件定義書で「何を作るか」を確認する。
  2. 設計書で「どう作るか」を確認する。
  3. MVP実装範囲定義書で「最初にどこまで作るか」を固定する。
  4. Codex向け実装指示書を使って、段階的に実装依頼する。
  5. 受け入れテスト仕様書で、完成判定を行う。
  6. 環境構築・デプロイ手順書に従って公開する。
  7. 本番が近づいたら、運用マニュアルとリハーサルチェックリストを追加する。

本資料は、謎解き企画用Webアプリの実装準備を目的とした設計ドキュメントです。要件確定後、実装状況に合わせて更新してください。
