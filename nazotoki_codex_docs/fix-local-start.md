## 目的

前回要件では、問題取得後に開始ボタンを押すまで回答できない仕様になっていました。

今回の修正では、企画上の仕掛けとして、**問題画像を表示する前から回答できる**仕様に変更します。

つまり、参加者は以下の2通りで回答できます。

1. 問題画像を表示する前に、タイトルや事前情報だけを見て回答する
2. 「画像を表示して開始」ボタンを押し、画像表示とタイマー開始後に回答する

## 前回要件からの変更点

前回要件のうち、以下は修正してください。

### 修正前

```txt
問題取得後、問題文・問題画像・回答欄を隠し、開始ボタンのみ表示する。
開始ボタン押下後に回答可能になる。
```

### 修正後

```txt
問題取得後、問題タイトルと回答欄は表示する。
問題画像だけを非表示にし、画像と同じ高さの点線枠プレースホルダーを表示する。
回答欄は開始前から使用可能にする。
「画像を表示して開始」ボタンを押すと、問題画像を表示し、同時にタイマーを開始する。
```

## 重要な仕様

### 1. 開始前から回答可能にする

問題取得後、画像を表示する前でも回答入力欄と送信ボタンを表示してください。

この状態では、まだタイマーは開始しません。

開始前に回答した場合も、ローカルで正誤判定してください。

* 正解なら、その時点で最終結果を確定する
* 不正解なら、解答回数を1回消費する
* 残り回数があれば、引き続き回答可能にする
* 解答回数上限に達した場合は `attempt_limit_exceeded` として終了する

### 2. 開始前に正解した場合

画像を表示する前に正解した場合は、以下の扱いにしてください。

```txt
finalStatus = "correct"
isCorrect = true
answerElapsedMs = 0
answeredBeforeReveal = true
```

`answerElapsedMs = 0` は、「画像表示後のタイマー開始前に正解した」という意味です。

可能であれば、`submissions` に以下のカラムを追加してください。

```sql
ALTER TABLE public.submissions
ADD COLUMN IF NOT EXISTS answered_before_reveal boolean DEFAULT false;
```

DBカラム追加が過剰であれば、最低限API上では `answeredBeforeReveal` を扱い、保存は既存カラムで対応しても構いません。

### 3. 開始前の不正解も解答回数に含める

画像表示前の回答も、通常の解答試行として扱ってください。

例:

```txt
maxAttempts = 3

画像表示前に1回不正解
↓
残り回数 = 2

その後、画像を表示して2回回答可能
```

### 4. 「開始ボタン」の意味を変更する

前回要件の開始ボタンは、今回から以下の意味に変更してください。

```txt
問題を表示して開始
```

ではなく、より正確には以下です。

```txt
画像を表示してタイマー開始
```

表示文言は以下のようにしてください。

```txt
画像を表示して開始
```

このボタンを押したときだけ、問題画像を表示し、タイマーを開始してください。

ボタン押下前はタイマーを開始しません。

### 5. タイトルは最初から表示する

問題取得後、回答前・画像表示前の時点で、問題タイトルは表示してください。

表示してよいもの:

* 問題タイトル
* 制限時間
* 解答可能回数
* 残り解答回数
* 回答欄
* 回答結果表示欄
* 画像プレースホルダー
* 「画像を表示して開始」ボタン

表示しないもの:

* 問題画像本体
* 画像内に含まれる問題情報

既存データに `title` が存在しない場合は、既存の問題名・問題番号・問題見出しに相当するフィールドを使用してください。
なければ、暫定的に `問題` や `第N問` の表示でも構いません。

### 6. 問題画像領域は、画像表示前から同じ高さを確保する

画像表示前後で回答欄や結果表示欄の位置が動かないようにしてください。

画像表示前は、実際の画像と同じ表示領域を確保し、点線枠だけを表示してください。

例:

```txt
+--------------------------------+
|                                |
|        画像はまだ非表示です       |
|                                |
+--------------------------------+
```

CSSイメージ:

```css
.question-image-frame {
  width: 100%;
  aspect-ratio: var(--question-image-aspect-ratio);
  border: 2px dashed #999;
  display: flex;
  align-items: center;
  justify-content: center;
}

.question-image-frame img {
  width: 100%;
  height: 100%;
  object-fit: contain;
}
```

実装上 `aspect-ratio` の取得が難しい場合は、既存の画像表示サイズに近い固定高さを使用してください。

例:

```css
.question-image-frame {
  min-height: 320px;
}
```

重要なのは、**画像表示前後で回答欄の縦位置が変わらないこと**です。

### 7. 回答欄と結果表示欄の位置を固定する

問題画像の表示・非表示によって、回答欄と結果表示欄が上下にずれないようにしてください。

画面構成は以下を推奨します。

```txt
[問題タイトル]

[画像領域]
- 画像表示前: 点線枠プレースホルダー
- 画像表示後: 同じ領域内に画像を表示

[画像を表示して開始ボタン]
- 画像表示前のみ表示
- 画像表示後は非表示または disabled

[回答欄]
- 画像表示前から常に同じ位置に表示
- 画像表示後も位置を変えない

[結果表示欄]
- 不正解、残り回数、正解、タイムアップなどを表示
- 表示内容が変わってもレイアウトが大きく動かないよう、最低高さを確保する
```

結果表示欄には `min-height` を設定してください。

例:

```css
.answer-result-area {
  min-height: 48px;
}
```

### 8. 状態名を必要に応じて見直す

前回要件の `ready` は「開始前で回答不可」の意味に近かったため、今回の仕様では意味が変わります。

可能であれば、以下のように状態を整理してください。

```ts
type PlayState =
  | "loading"
  | "preview"
  | "active"
  | "completed"
  | "submitting"
  | "submitted"
  | "error";
```

意味:

```txt
preview:
  問題取得済み。
  タイトル・回答欄・画像プレースホルダーを表示。
  画像は非表示。
  タイマー未開始。
  回答は可能。

active:
  画像表示済み。
  タイマー進行中。
  回答可能。

completed:
  正解、タイムアップ、または回数上限到達で終了。
```

既存実装の都合で `ready` を使い続けても構いません。
ただし、その場合も `ready` 状態で回答可能にしてください。

### 9. sessionStorage 復元仕様も変更する

ページ更新時の復元仕様も今回の仕様に合わせてください。

#### preview状態で更新した場合

```txt
画像は非表示のまま
タイマーは未開始のまま
回答欄は表示
それまでの不正解回数・残り回数は復元
```

#### active状態で更新した場合

```txt
画像表示済み
タイマーは startedAtWallMs / deadlineAtWallMs から復元
回答欄は表示
それまでの不正解回数・残り回数は復元
```

#### completed状態で更新した場合

```txt
完了結果を復元
未送信なら最終結果送信を再試行
```

### 10. タイムアップは画像表示後のみ発生する

タイマーは「画像を表示して開始」ボタンを押すまで開始しません。

そのため、画像表示前の `preview` 状態ではタイムアップしません。

ただし、解答回数上限に到達した場合は、画像表示前でも `attempt_limit_exceeded` として終了します。

### 11. 画像を表示しないまま正解した場合は、タイマーを開始しない

画像表示前に正解した場合、画像を表示する必要はありません。

この場合は即座に完了状態にし、最終結果を送信してください。

保存内容の目安:

```json
{
  "finalStatus": "correct",
  "isCorrect": true,
  "finalAnswer": "回答内容",
  "answerElapsedMs": 0,
  "attemptCount": 1,
  "answeredBeforeReveal": true
}
```

### 12. ハッシュ判定仕様は維持する

前回要件どおり、ローカル判定では正解文字列をクライアントに直接渡さないでください。

* `/api/current-question` に正解文字列を含めない
* `validation.correctAnswerHashes` を返す
* クライアント側で入力値を正規化し、SHA-256化して比較する
* F12 Networkタブで正解文字列が直接見えない状態を維持する
* `/api/submit-answer` ではサーバー側でも `finalAnswer` を再判定する

### 13. API送信仕様

最終結果送信APIに、可能であれば以下を追加してください。

```json
{
  "answeredBeforeReveal": true
}
```

`answeredBeforeReveal` は以下の条件で `true` にします。

```txt
画像表示前の preview 状態で正解した場合
```

それ以外は `false` にしてください。

## 受け入れ条件

以下を満たしてください。

1. 問題取得後、問題タイトルが表示される
2. 問題取得後、問題画像は表示されない
3. 問題画像の代わりに、画像と同じ領域の点線枠が表示される
4. 問題取得後、画像表示前でも回答欄が表示される
5. 画像表示前でも回答できる
6. 画像表示前に不正解した場合、API通信せず、残り解答回数が減る
7. 画像表示前に正解した場合、`answerElapsedMs = 0` で最終結果が送信される
8. 画像表示前に正解した場合、`answeredBeforeReveal = true` として扱われる
9. 「画像を表示して開始」ボタンを押すと、画像表示とタイマー開始が同時に行われる
10. 画像表示後は、従来どおりローカルタイマーで残り時間が減る
11. 画像表示前後で、回答欄の位置がずれない
12. 画像表示前後で、結果表示欄の位置が大きくずれない
13. 結果表示欄には最低高さが確保されている
14. preview状態でページ更新しても、画像非表示・タイマー未開始・回答可能状態が復元される
15. active状態でページ更新しても、画像表示済み・タイマー進行状態が復元される
16. ハッシュ判定により、正解文字列は参加者向けAPIに直接露出しない
17. 既存の複数回回答、タイムアップ、最終結果送信、ランキング表示を壊さない
